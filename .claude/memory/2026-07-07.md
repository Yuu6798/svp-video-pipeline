### Design Decisions

- **discipline テストの配置**: svp-video-pipeline はネスト構成（ルートに
  CLAUDE.md、`svp_pipeline/` 配下に pyproject.toml/src/tests）のため、
  discipline テストを `svp_pipeline/tests/discipline/` に置き、CI の
  working-directory 設定（`svp_pipeline/` 内で `pytest tests/ -q`）を
  無改修で通す設計にした。`_helpers.py` の `REPO_ROOT` は
  `parents[3]`（svp_pipeline/tests/discipline/ から 3 階層上）でリポジトリ
  ルートを指す。
- **README 350 行キャップの新設**: 移植元にはない新規テスト
  `test_readme_line_cap.py` を追加し、ルート `README.md` と
  `svp_pipeline/README.md` の両方を 350 行 hard limit で CI 対象化した
  （CLAUDE.md の README 管理ポリシーを初めて実行可能な形で enforce）。
  `svp_pipeline/README.md` が現時点で 343 行と hard limit 目前だったため、
  STATUS.md の Next-Issue Queue に分離タスクを P2 でシードした。
- **スコープ外項目の記録**: 型チェッカー導入、CI markdown-lint の実質化、
  テスト規約（モック不使用推奨）と実態（`tests/fixtures/mock_*.py`）の
  乖離は本移植のスコープ外と判断し、STATUS.md の Next-Issue Queue に
  P3 として記録した（次セッションでの着手判断に委ねる）。
- **AGENTS.md / skills の適応**: ugh 固有のロードマップ参照
  （roadmap_goal1 等）や CompositionScore/PhysicalLayer 固有チェックは
  svp 固有の対象（SVP schema `schema/svp.py` 五層、バックエンド
  インターフェース `generator/image_base.py`、`tests/fixtures/` の mock
  バックエンド、`samples/` の SVP JSON）に置換した。
